# 👕 CM3070 — AI-Powered Intelligent Virtual Fashion Try-On

> Final-year BSc Computer Science project combining **IDM-VTON**, **Florence-2**, and **Qwen2.5** into one end-to-end AI fashion assistant.

---

## 📌 Project Overview

This project explores how multiple pre-trained AI models can be orchestrated to solve a practical fashion problem: allowing a user to preview a garment on a person image, understand the garment visually, and receive styling recommendations from the same workflow.

The system accepts:

- a **person image**
- a **garment image**
- optional **occasion**
- optional **style preference**

It then performs three main stages:

1. **Garment understanding with Florence-2**
   - generates a detailed garment description
   - extracts visible text or logos through OCR

2. **Fashion recommendation with Qwen2.5**
   - receives the Florence-2 description and OCR result
   - combines them with the selected occasion and style preference
   - generates practical styling advice

3. **Virtual try-on with IDM-VTON**
   - receives the person image
   - receives the garment image
   - receives the garment description generated by Florence-2
   - produces the final virtual try-on image

The final system therefore does more than run three separate AI models. The models are connected so that the output of one component becomes input to another.

# 🏗 Final System Architecture

A major implementation decision was to avoid forcing all models into one Python environment.

IDM-VTON required a specialised GPU environment and several dependency fixes, while Florence-2 and Qwen were more stable in Google Colab. The final system therefore uses a distributed architecture.

```text
                         USER
                          │
              ┌───────────┴───────────┐
              │                       │
        Person Image             Garment Image
              │                       │
              │                       ▼
              │                  Florence-2
              │                 ┌─────┴─────┐
              │                 │           │
              │           Description      OCR
              │                 │           │
              │                 └─────┬─────┘
              │                       │
              │                       ▼
              │                     Qwen
              │                       │
              │                 Styling Advice
              │
              │
              └──────────────┐
                             │

                             │          Kaggle GPU
Florence Description ────────┘              │
                                            ▼
                                    Virtual Try-On Image
                                            │
                                            ▼
                                     FINAL OUTPUT
```

# 🧠 Important Engineering Work

A substantial part of the project involved making IDM-VTON run reliably within limited GPU resources.

## CUDA Out-of-Memory Problem

The original configuration exhausted the available GPU memory during VAE encoding and diffusion inference.

The final low-memory configuration used:

```python
pipe.enable_vae_slicing()
pipe.enable_vae_tiling()
pipe.enable_sequential_cpu_offload(...)
```

The custom IDM-VTON garment UNet encoder required its own offload handling because it was attached separately from the standard registered Diffusers pipeline components.

The final notebook reports:

```text
Custom garment UNet encoder CPU offload: ON
LOW VRAM MODE ENABLED
 - VAE slicing: ON
 - VAE tiling: ON
 - Sequential CPU offload: ON
```

## OpenPose Device Mismatch

A separate issue occurred because OpenPose weights had been moved to CPU while its input tensor was still being moved automatically to CUDA.

The preprocessing code was patched so that input tensors follow the device of the OpenPose model.

The final implementation runs OpenPose on CPU before returning resources to the main VTON process.

## CPU / CUDA Tensor Mismatch

The custom garment UNet encoder also required explicit device-aware handling so its timestep embeddings and model weights remained on compatible devices during inference.

These fixes allowed the diffusion process to complete successfully instead of failing before generation.

# ⚠️ Current Limitations

The project is intended as a **visual fashion preview and styling assistant**, not as a physical fitting or size-prediction system.

Current limitations include:

- IDM-VTON inference is relatively slow
- fine logos and complex patterns may not always be preserved perfectly
- visual realism varies between images
- unusual body poses can be more difficult
- automatic body masking depends on visible body structure
- OCR quality depends on text size and visibility
- styling recommendations depend on the accuracy of the garment description
- temporary Gradio URLs must be refreshed when the Kaggle session restarts
- the system currently requires two cloud environments for the complete GPU workflow

---

# 🔐 Privacy and Responsible Use

The project processes uploaded person photographs, so privacy is an important consideration.

The intended design principles are:

- only use images the user has permission to process
- avoid unnecessary long-term storage
- clearly communicate that outputs are AI generated
- do not represent virtual try-on as exact physical fit
- acknowledge possible model bias across body shapes, poses, skin tones, and garment types
- avoid making unsupported sizing or body-related claims
